# Propositions de règles pour le kit : dépôt Git et gros fichiers

À valider le 2026-11-18 (cycle « proposer, valider, appliquer », rule `00-organisation`). Rien n'est encore appliqué : une fois validées, les modifications vont dans les trois copies du kit (SSA_Capsule, kouzia-modele-site, kouzia-boite-a-outils) et une ligne s'ajoute à `.claude/journal-kit.md`.

## Ce qui s'est passé (2026-11-17)

- `git push origin refonte:refonte` refusé par GitHub : `docs/source/existant/fichiers/media-167ec4d34570.mp4` pèse 528 Mo, au-delà de la limite de 100 Mo par fichier ; deux autres vidéos de 87 et 54 Mo dépassent la taille conseillée de 50 Mo.
- Cause : le script d'audit `.claude/skills/livrables/scripts/audit-existant.mjs` (lignes 490 à 510) télécharge chaque vidéo du site actuel pour vérifier avec ffmpeg qu'elle n'est pas tronquée, puis la laisse dans `docs/source/existant/fichiers/`. Le `.gitignore` excluait les vidéos de `docs/source/existant/medias/`, pas celles de `fichiers/`.
- Correction faite dans ce projet : les trois vidéos retirées des 5 commits non poussés (branche de sauvegarde `sauvegarde/refonte-avant-retrait-videos`), fichiers gardés sur le poste, `.gitignore` complété.
- Erreur de l'agent pendant la correction : la réécriture de l'historique a aussi supprimé les trois vidéos de l'arbre de travail ; elles ont été restaurées depuis la branche de sauvegarde, empreintes identiques vérifiées.

## Proposition 1 : l'audit ne garde pas les vidéos

- **Fichier** : `.claude/skills/livrables/scripts/audit-existant.mjs`, boucle des médias (lignes 490 à 510).
- **Texte** : écrire la vidéo dans un fichier temporaire (`os.tmpdir()`), la vérifier avec ffmpeg et ffprobe, puis l'effacer ; ne garder dans l'inventaire que la taille, la durée annoncée et le statut (complet, tronqué). Commentaire à ajouter : « Vidéo vérifiée dans un fichier temporaire puis effacée : elle n'a rien à faire dans le dépôt (528 Mo sur la SSA, refusé par GitHub). »
- **Raison** : la vérification n'a besoin du fichier que le temps de la lire ; le garder remplit le dépôt sans servir à rien (l'import des contenus lit ses propres copies).

## Proposition 2 : `.gitignore` du modèle

- **Fichiers** : `kouzia-modele-site/.gitignore` et `.claude/skills/web-new-site/modeles/php-statique/.gitignore`.
- **Texte** :
  ```
  # Vidéos et sons relevés sur le site actuel par l'audit : gardés sur le poste, jamais versionnés.
  docs/source/existant/**/*.mp4
  docs/source/existant/**/*.webm
  docs/source/existant/**/*.mov
  docs/source/existant/**/*.mp3
  ```
- **Raison** : filet de sécurité si une vidéo arrive quand même dans `docs/source/existant/` (ancienne version du script, copie à la main).

## Proposition 3 : contrôle de taille avant chaque commit

- **Fichier** : `.claude/skills/web-audit/scripts/check-repo.mjs` (dans `make verify`).
- **Texte** : refuser tout fichier suivi par Git de plus de 50 Mo (taille conseillée par GitHub ; refus au-delà de 100 Mo), avec le message « fichier trop lourd pour le dépôt : l'exclure (.gitignore) ou le stocker ailleurs ».
- **Raison** : le refus n'apparaît qu'au moment du push, quand le fichier est déjà dans plusieurs commits et qu'il faut réécrire l'historique ; le contrôle l'arrête avant le premier commit.

## Proposition 4 : retirer un fichier de l'historique sans le perdre

- **Fichier** : `.claude/skills/web-git/SKILL.md`, section « Hygiène ».
- **Texte** : « Retirer un fichier de l'historique (fichier trop lourd, secret) : créer d'abord une branche de sauvegarde, copier le fichier hors du dépôt, puis réécrire seulement les commits non poussés ; la réécriture le supprime aussi de l'arbre de travail. Après le push réussi, supprimer la branche de sauvegarde. »
- **Raison** : erreur constatée le 2026-11-17 (vidéos effacées du poste par la réécriture, récupérées grâce à la branche de sauvegarde).
